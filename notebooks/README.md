# Notebooks

`01_results_overview.ipynb` — everything the pipeline produced, in one pass:
QC → alignment → the dual-RNA-seq split → counting → expression matrices, plus
what the data can and cannot support. It reads only pipeline outputs, so it is
safe to re-run any time `make` has produced something new.

## Running it

```bash
scripts/viz-env.sh                       # once: builds ~/.venvs/viz (about a minute)
~/.venvs/viz/bin/jupyter lab             # then open notebooks/01_results_overview.ipynb
```

Headless, no browser — re-executes every cell and refreshes `figures/`:

```bash
~/.venvs/viz/bin/jupyter nbconvert --to notebook --execute --inplace \
    notebooks/01_results_overview.ipynb
~/.venvs/viz/bin/jupyter nbconvert --to html notebooks/01_results_overview.ipynb
```

`01_results_overview.html` is the rendered version — open it directly, no kernel
needed. Figures are also written individually to `figures/` (gitignored; both
are regenerated by the commands above).

To run Jupyter on a compute node instead of here, start a session with
`scripts/claude-session.slurm`, then from your laptop:
`ssh -L 8888:<node>:8888 ceres.scinet.usda.gov` and point a browser at the URL
Jupyter prints.

## Environment

Deliberately separate from the pipeline's `rnaseq` conda env: adding a plotting
stack to it risked moving the pinned aligner/counter versions that produced
these results. Pins are in `requirements.txt`.

Note this is a venv rather than conda — `mamba env create` solves fine on Ceres
but dies partway through linking files into home (numpy fails, transaction rolls
back). pip wheels install cleanly in about a minute.
